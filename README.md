# Лабораторная 3

### Общая структура лабораторных

Все задания описаны в корневом файле `README.md`.

Ваши решения вы публикуете в этом же репозитории.

Для каждого задания вы создаете папку `task-XX`, где `XX` - номер задания (возможно, начинающееся с 0).
В эту папку вы складываете все файлы, относящиеся к решению. Как правило, это будет bash скрипт с названием `solution.sh`.
Решения проверяются автоматически, поэтому важно соблюдать структуру проекта.

Ваши решения будут запущены в Docker-образе, подготовленном для этой лабораторной.
Если вы хотите прогнать свой скрипт у себя локально в том же окружении, изучите файл с конфигурацией GitHub Actions
для проверки вашей лабораторной, и подтяните соответствующий образ.

**Изменения в папке `.github` запрещены.**

Тесты публичные, их можно посмотреть в Docker-образе. 
Работы дополнительно проверяются вручную, поэтому просто захардкодить ответы нельзя.

### Сдача лабораторной

При создании репозитория у вас автоматически создался Pull Request из ветки main в ветку, 
в которой хранится первоначальное состояние вашего репозитория.

При каждом коммите в main у вас автоматически будут прогоняться тесты, после чего вы получите отчет
о результатах в виде комментария в PR.

После наступления дедлайна преподаватель вручную смотрит все PR студентов и выставляет в ведомость баллы за задания с пройденными тестами. 
Если вы сдаете после дедлайна, запросите ревью и/или напишите преподавателю в личные сообщения, чтобы он проверил.

## Задание 1

**Стоимость: 5 баллов.**

`wget URL` — команда, которая позволяет скачивать файлы из интернета. Напишите последовательность команд, которые будут выполнять следующее:
- создавать директорию `task1` (все остальные файлы должны быть в ней)
- скачивать [файл](https://gist.githubusercontent.com/tochilinak/71855d5e698dd60fbeca0e50e5b12e6b/raw/62514a1188c54f726983449e572663f90da99aec/alice_in_wonderland.txt)
- создавать файл `statistics`, в котором на отдельных строках будут располагаться следующие величины:
  - количество строк в файле
  - количество слов в файле
  - количество слов Alice (вне зависимости от регистра), встречающихся в файле
  - количество строк, в которых встречается слово Alice (вне зависимости от регистра)
  - топ-10 самых часто встречающихся слов в тексте, частота их повторений (перед самим словом), в порядке убывания частоты, по слову на строке, с зависимостью от регистра. Дефисы и прочие знаки, не являющиеся буквами, не считаются частью слова.
- создавать файлы `ALICE.txt` и `alice.txt`, содержащие текст файла в верхнем регистре и в нижнем регистре соответственно
- создавать файл `alice_shuf.txt`, содержащий 10 случайных строк из файла с их номерами
  - Используйте команду `shuf`. Для детерминированности в качестве `--random-source` возьмите файл `/workspace/data/random-source`.
 
За правильный файл `statistics` вы получаете **3 балла**.

За файлы `ALICE.txt` и `alice.txt` вы получаете **1 балл**.

За файл `alice_shuf.txt` вы получаете **1 балл**.

## Задание 2

**Стоимость: 1.5 балла.**

Команда `lspci` предназначена для отображения информации об устройствах на шине pci, установленных в системе.
Ключик `-v` отображает подробную информацию. Разберитесь, как вывести драйвер вашей видеокарты. 
В этом вам поможет следующее знание:
- Видеокарта в списке `lspci` носит название `VGA compatible controller` (достаточно искать слово VGA)
- Имя драйвера можно посмотреть на строчке `Kernel driver in use: …` в подробном выводе команды
- У команды `grep` есть ключики `-A` и `-B`, прочитайте о них на страничке man или в гугле

**Так как в докере `lspci` не работает, возьмите подготовленный вывод `lspci -v` из файла `/workspace/data/lspci.txt`. Локально рекомендуется прогнать команду на настоящей машине.**
